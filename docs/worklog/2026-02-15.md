## 완료 작업

### Task #11: 구조화된 프롬프트 V2 설계 및 적용

**목표:** Phase 1 파일럿 결과 4가지 문제(정의조 FP, 목적조 FP, 주체 불일치 무시, 일관성 부족) 해결

#### 변경 파일 (3개)

| 파일 | 변경 내용 |
|------|----------|
| `ast_parser.py` | LawAST에 `action_modality` 필드 추가, SYSTEM_PROMPT V2, 캐시 키 버전 |
| `nli_evaluator.py` | NLIResult에 `component_analysis` 필드 추가, NLI_SYSTEM_PROMPT V2, 캐시 키 버전 |
| `pilot_test.py` | 조문 필터링(정의조/목적조/기본이념 제외), component_analysis 출력 |

#### 1. ast_parser.py — LawAST 구조 확장

- `action_modality` 필드 추가: 8개 분류값 (의무/금지/허용/신고/인가허가/선언/벌칙/Not Specified)
- SYSTEM_PROMPT V2 적용:
  - 도메인 지식 섹션: 정의조/목적조/기본이념 → `action_modality = "선언"` 분류
  - Few-shot 예시 2건 (실체 규정 + 정의 조항)
  - JSON 출력 스키마에 `action_modality` 포함
- `PROMPT_VERSION = "v2"` → 캐시 키에 반영 (V1 캐시 자동 미스)

#### 2. nli_evaluator.py — NLI 프롬프트 구조화

- `component_analysis` 필드 추가 (노드별 분석 결과 저장)
- NLI_SYSTEM_PROMPT V2 적용:
  - **Hard Rules 3개**: 선언형 조문(C≤0.1), 주체 불일치(C≤0.3), Not Specified(무관 처리)
  - **Prompt Chaining**: Step 1(규칙 확인) → Step 2(노드별 비교) → Step 3(종합 스코어)
  - **Few-shot 예시 3건**: 충돌(인가→신고), 무관(다른 주체), 무관(선언형)
- `_build_user_prompt`에 `Action_modality` 라인 추가
- `evaluate()`에서 `component_analysis` 추출/캐시 처리
- `PROMPT_VERSION = "v2"` → 캐시 키에 반영

#### 3. pilot_test.py — 조문 필터링 + 로깅

- `SKIP_ARTICLE_TITLES = {"목적", "정의", "기본이념"}` → fallback에서 선언형 조문 제외
- 안전장치: 전부 건너뛰면 다시 포함
- 결과에 `component_analysis` 필드 포함
- 출력에 노드별 분석 표시 (`S=일치 | A=충돌` 형식)

#### 적용 기법 (Prompt Engineering Guide)

| 기법 | 적용 내용 |
|------|----------|
| Context Engineering | `action_modality` enum 추가, 조문 유형별 도메인 지식 주입 |
| Prompt Chaining | 선행 규칙 → 노드별 비교 → 종합 스코어 순차 분석 |
| Few-Shot Examples | AST 2건 + NLI 3건 예시 |
| Generated Knowledge | 한국 법률 조문 유형 가이드 (정의조/목적조/기본이념) |

#### 기대 효과

| 지표 | V1 (현재) | V2 (기대) |
|------|----------|----------|
| 정의조 Contradiction | 0.0~0.7 (불일치) | ≤ 0.1 (일관) |
| 목적조 Contradiction | 0.5~0.7 | ≤ 0.1 |
| 주체 불일치 시 C | 0.5~0.7 | ≤ 0.3 |
